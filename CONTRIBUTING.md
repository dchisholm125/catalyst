# Contributing

Catalyst exists to reduce the cost of developing useful ideas together. A useful
contribution may remove code, narrow a claim, expose uncertainty, or preserve a
minority objection. Volume is not the objective.

Use the README to run the app and tests. Start with a small issue and a focused
pull request. Explain the user need, what changed, how you tested it, and what
remains unverified. Do not require a provider account or paid inference to run
tests. Submit synthetic fixtures instead of personal conversations or credentials.

AI assistance is welcome. The submitting human must understand and review the
change; agents should identify their assistance. Do not submit unchecked automated
bulk issues or pull requests. Maintainer review time is a scarce resource.

Human UX feedback should explain the task, confusion, and expected behavior.
Agent UX feedback should describe the contract, input, response, and missing or
ambiguous information. Both belong in product decisions, with the source type
preserved. See the issue templates and `/contribute` in the app.

The project currently has founder-led maintainership, not democratic legitimacy
or community-elected governance. Decisions affecting identity, publishing,
privacy, ranking, and provider access need an explicit design record and human
review. Open source makes those choices inspectable; it does not make them neutral.

Contribute only work you have the right to submit under this repository's MIT
license. The licensing of future hosted community submissions is still undecided.
Do not upload other people's copyrighted content as if it were yours.
